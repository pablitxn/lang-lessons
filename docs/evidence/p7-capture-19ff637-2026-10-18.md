## Findings

### C1 — P2: common explicit secret formats survive redaction into Phoenix

Location: `server/debug-evidence.ts:24–29`, newly reachable for non-synthetic provider transcripts through `server/provider-capture.ts:84` and `server/index.ts:31–33`.

A completed transcript containing `{"password":"SYNTHETIC_PASSWORD"} Authorization: Basic U1lOVEhFVElDX09OTFk=` reaches the actual Phoenix debug sink with the JSON password and Base64 credential still present in `input.value`. The secret-label expression does not accept the closing quote before `:`; for Basic authentication it removes only the word `Basic`, leaving the credential. The expression existed at the synthetic-only base, but this PR makes the path eligible for live content.

Reproduction is `P7 reproduction: JSON password and Basic authorization survive the live-enabled redaction path` in the review test. It injects a provider-shaped event and reads actual in-memory OpenTelemetry span attributes. The test asserts the defective current behavior, not a passing security property. Redact quoted key/value forms and complete supported authorization/cookie values before creating spans; add negative assertions for these cases. This is not a claim that arbitrary spoken secrets can be perfectly detected, or that the server key was exposed.

### C2 — P2: shutdown overlooks observers already draining and drops accepted spans

Location: `server/provider-capture.ts:61–69,92`; composed shutdown at `server/index.ts:39–41`.

`stop()` removes the handle from `active` immediately, before the queued records finish. `shutdown()` waits only handles still in `active`. On socket loss or a previously requested stop, shutdown returns while that observer still has accepted work. The application then shuts down telemetry, and subsequent queued spans are dropped.

Two independent reproductions establish this: a held sink proves `shutdown()` resolves before pending accepted work; the actual `PhoenixTelemetry` sink with an injected exporter receives ten synthetic completed transcript events, then socket close and the application shutdown sequence. Only **1/10** accepted spans exported. Calling/awaiting the original handle afterward completes its queue too late. Track draining handles independently and include their existing bounded stop promises in shutdown. Keep the bounded best-effort behavior; do not make shutdown wait forever on an unavailable exporter.

## Verified behavior and scope limits

- Real loopback `ws` frames traverse projection and capture, including two distinct canonical sessions using the same event ID. Their exported records remain independently attributed. Spoofed session fields, raw audio fields and audio delta events do not cross the sink boundary.
- Broker attaches capture only after durable creation receipt; failed provider hangup retains capture; confirmed cleanup stops it. Observer errors do not invent learner disconnect observations. F6 cancellation during reserved-but-undispatched creation still yields zero provider calls.
- Fixed sideband provider URL, validated call ID, server-only Authorization header, disabled redirects/compression, payload and handshake limits. No browser-controlled export destination, raw provider error body logging, audio persistence API/table/file write, or professor raw-trace endpoint was introduced.
- Explicit `PHOENIX_CAPTURE_TRANSCRIPTS=true` is additionally required alongside enabled application/voice and a configured sink. Existing collector configuration rejects remote plaintext HTTP and URL credentials/query/fragment; loopback HTTP is permitted. Destination is server-controlled and shared with configured metadata tracing. SDK disable prevents the sink. Tests use an injected exporter, not the configured URL.
- Queue bounds: 64 pending projected events per observer, 64 KiB messages, 16k-character text, 2048 replay fingerprints per segment, 256 retained segment recorders per process. **The 257th distinct segment cannot capture until process restart**, even if older sockets stopped. This is an explicitly documented capacity limitation, not a temporary concurrency limit. Capture failures do not stop tutoring. The SDK has its own 128-span queue; recorder acceptance is not collector delivery acknowledgment.
- No automatic reconnect, startup scan, missed-event backfill or durable replay archive. Deduplication is process-local; restart clears it. A socket outage can leave the rest of a call uncaptured. Retention/deletion and live provider/device/Phoenix acceptance remain outstanding; they do not invalidate the user's authorization to implement capture now.
- No recorded audio persistence found in this delta. Projection excludes audio payloads; this review does not claim that regex filtering can identify every arbitrary encoding disguised as transcript text.
