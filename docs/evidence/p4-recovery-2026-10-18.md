# P4 interrupted-session recovery amendment

Additive implementation base: `9c46a57108ef3d773fa66f53f93a9511a16ec768` on
PR15, originally based on frozen interface commit
`8316baa745acf0280181cf72ef6fa400561dcd05`. The PR records the new exact head.
This amendment supersedes the earlier P4 receipt's unselected manual-recovery UI
only: the parent now explicitly authorizes resume/finalize, local pending progress
with durable sync/replay, and manual failed-feedback retry. Original receipts
remain intact. No new duration, retention, automatic paid retry or audio capture.

## Delivered P4 behavior

- `SessionRecovery` renders Resume session / Finalize session for an authenticated
  interrupted session. Loading/status refresh only reads metadata. Explicit resume
  restores the P5 queue through an injected port and mounts the SAME session.
  Neither operation starts audio or creates another exercise session.
- An authoritative recovered `hadConnectedCall` seeds lifecycle confirmation.
  Called-session finalization uses the existing dialog and frozen coordinator;
  no-call finalization has no popup. Cancel preserves the restored queue/session.
- Final progress must flush before close/navigation. Rejected progress remains
  open with a visible error. A new explicit Retry finalization action reuses the
  coordinator's frozen operation/payload after ambiguous close; after preparation
  failure it prepares/flushes again. There is no automatic close retry.
- Closed session feedback renders not-requested, pending, running, saved, failed
  (still pending with a manual retry button), or insufficient evidence. No comment
  text or evidence is invented. Failed feedback alone permits explicit retry;
  pending/running/saved/insufficient states do not start another request.
- Duplicate clicks share the in-flight operation. An uncertain feedback reply
  retains the same retry operation ID for manual replay within this controller.
  Durable replay and uniqueness after reload remain the server's responsibility.
- Synchronous account/session invalidation aborts outstanding requests, clears
  displayed record/lifecycle/error state and detaches the old queue handle. Late
  reads, queue restoration and feedback results cannot restore old account UI.
  Detaching is not deletion of durable pending records or acknowledged history.
- Native confirmation supports Escape, initial cancel focus and focus restoration
  to Finalize. Browser validation exposed a disabled-trigger focus bug; it was
  corrected by an explicit return-focus ref and next-frame restoration.

## Exact root / P2 / P5 wiring requests

The new interfaces are P4-local integration ports in `src/app/session-recovery.ts`,
not an alternative server contract or shared-barrel change. Sole integrator task
`01a14e4c-74cd-7047-9c85-194a390d3001` owns adapters/wiring and contract promotion.

1. Root discovers the returning account's interrupted session through an
   authenticated P2 read, then constructs `createSessionRecovery(ports)` and calls
   `load()`. Render `<SessionRecovery recovery={controller} exitTarget={target} />`.
   Root owns discovery/list selection, route registration and component lifetime.
2. `identity` is `{ accountId, sessionId }`. `read(identity, signal)` returns
   `{ accountId, sessionId, session: SessionSnapshot, hadConnectedCall, feedback }`.
   P2 must check authenticated ownership; IDs are not authentication. Persisted
   call history, not current transport state or a guess, supplies the boolean.
3. `preparePractice(record, signal)` restores P5's IndexedDB queue and returns
   `{ lifecycle, release }`. Create the existing P4 lifecycle with the canonical
   session ID, **`hadConnectedCall: record.hadConnectedCall`**, P5's real
   freeze/release/flush methods, P2 SessionCommands, and root `isCurrent`/navigate.
   No second exit coordinator. `release()` only detaches account-scoped handles.
   It must not wipe pending writes/history. Honor aborts and release late handles.
4. `resume(record)` mounts the same canonical session and P5-restored exercise,
   draft and progress state, with tutor offline. Pass recovered call history to
   the mounted LessonSession's lifecyclePorts too. Root must arrange queue-handle
   ownership across recovery-view unmount and active-lesson mount; do not clear
   durable records or depend on a disposed controller's memory.
5. P5 owns local IndexedDB enqueue during practice, account/session partitioning,
   durable pending operation IDs, idempotent server sync, acknowledgment/queue
   removal, draft restoration and daily history across visits. P4 has no queue
   implementation or retry timer and never clears those records. App-local queue
   payloads must exclude audio/transcripts; Phoenix instrumentation is separate.
6. P2 owns recovery metadata, final journal fence, replay receipts, one feedback
   job/comment per session and persisted feedback states. `retryFeedback` accepts
   `{ accountId, sessionId, operationId }` plus AbortSignal and returns the same
   RecoveryRecord identity. It must idempotently enqueue/reconcile the SAME job,
   never create another stored comment. P6 owns grounded generation and explicit
   insufficient-evidence handling. No provider request originates in this UI.
7. Root must synchronously invoke the `subscribeInvalidation` listener on logout,
   account switch or superseded recovery selection, and supply `isCurrent` to BOTH
   recovery and lifecycle. Dispose on unmount. Create a fresh controller after
   identity changes; never reuse a previous account's controller/queue handle.
8. P2/root must reconcile an abandoned active call segment before restoring a
   lifecycle or atomically during close. Frozen SessionCommands exposes no recovery
   enumeration/connected receipt or active-segment metadata; P4 does not invent a
   server endpoint, resurrect an old media call, or assert that gap is solved.
9. Root may navigate after close; show feedback state from an authenticated closed
   session read on the destination/history view. Recovery's manual finalization
   retry refreshes its status when the view remains mounted. No polling or paid
   retry schedule is installed.
